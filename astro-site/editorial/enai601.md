# ENAI601 시리즈 편집 지침

## 글의 목적과 독자
- 처음 배우는 학생이 교안·캡션·손필기를 따로 열지 않고도 글 안에서 이해와 복습을 마칠 수 있게 쓴다.
- 독자에게 개념을 설명하는 독립적인 블로그 글로 쓴다. 작성자와 AI의 대화나 공동 학습 경험을 전제하지 않는다.
- “우리가 오래 붙잡았던 질문”, “대화에서 공부한 흐름”처럼 작성 과정을 회고하지 않는다. 질문은 개념상 필요한 이유에서 제시한다.

## 서문
- 이 단원이 ENAI601에서 왜 필요한지, 어떤 문제를 해결하며 앞뒤 단원과 어떻게 연결되는지 설명한다.
- 자료 대조·필기 페이지·작성 과정·검산·그림 제작·보충 내역을 나열하지 않는다.
- 출처와 보충 범위는 글 끝에 모으고 서문에서 반복하지 않는다. 안내표에는 페이지 번호 대신 학습 개념과 질문을 쓴다.

## 설명과 표기
- 낯선 기호와 용어를 이미 안다고 가정하지 않는다. 영어 용어와 한국어 뜻, 기호 읽는 법을 설명한다.
- 구체적인 예와 말로 된 설명에서 시작해 그림, 일반 정의식과 증명으로 연결한다.
- 정의의 가정, 충분조건과 필요조건, 차원과 주변 공간, 극한과 실제 달성을 구별한다.
- 원고의 학습 흐름을 유지하되 설명이 빠진 연결과 예제를 보충한다. 불필요한 범위 확장은 하지 않는다.

## 그림
- 공간적 직관이 필요한 개념에는 정확한 좌표·함수식으로 그린 그림을 붙인다.
- 여러 개념의 그림을 멀리 몰아놓지 말고 해당 설명 바로 아래에 배치한다.
- 포함·제외되는 점, 경계, 무한 방향, 축척을 명확히 표시한다. 그림 안의 레이블은 영어로 쓰고 한국어 설명은 본문에 둔다.
- 좌표·부호·제약조건을 검산하고, 새로 만든 그림의 실제 표시를 확인한다.

## 교안 원문과 출처
- “교안은 …한다”로 설명을 끝내지 않는다. 그 이해에 필요한 원문·정의·수식을 배경이 다른 인용 블록에 넣는다.
- 실제 교안에서 확인한 내용만 인용하고 Module과 절 제목을 표시한다. 수식을 웹용 LaTeX로 옮길 때 기호·조건·의미를 유지한다.
- 발췌에서 빠진 조건, 기호 변경, 오류 정정과 보충 설명은 인용 밖에서 명시한다. 교안의 오류를 그대로 정답처럼 가르치지 않는다.
- 인용 직후 뜻과 적용 조건, 필요한 예제를 설명해 독자가 다른 파일을 다시 열 필요가 없게 한다.
- 수업은 “수업”으로 표현한다. 캡션 처리 과정이나 AI가 작성했다는 표현을 본문 출처 안내에 넣지 않는다.

## 확인 문제와 해설
- 각 문제 바로 아래에 “정답과 해설 펼치기”를 둔다.
- 펼친 정답·해설은 본문과 구분되는 배경으로 표시한다. 밝은 모드와 다크모드 모두 테마 색상을 사용한다.
- 답만 적지 않고 적용한 정의, 계산 단계, 결론이 나오는 이유와 흔한 오해를 설명한다.

## 검증과 완료 보고
- 작업 전에 완료 조건과 필요한 검증을 짧게 정하고, 변경에 필요한 수식·코드·빌드·배포 확인만 수행한다.
- 새 실패나 미해결 문제가 없으면 같은 검증을 반복하지 않는다. 같은 문제가 수정 후에도 두 번 반복되면 접근법을 재검토한다.
- 사이트 육안 검증은 기본적으로 사용자에게 맡긴다. 별도 요청 없이 화면 폭·테마별 브라우저 순회나 스크린샷 수집을 하지 않는다.
- 구현·빌드·화면·실제 동작 확인을 구분해 보고한다. 확인하지 않은 것은 확인했다고 말하지 않는다.
- 완료 시 사용자가 직접 볼 위치와 기대되는 모양·동작을 구체적으로 요청한다.

## 현재 적용 범위
- 모든 게시물 본문의 자간은 -0.020em으로 통일한다. 코드와 수식은 기존 간격을 유지한다.
- 목록은 페이지당 최대 10개다. 시리즈 페이지는 내용 순서의 역순, 글 안의 시리즈 목록은 1번부터 표시한다.
- 이 파일을 ENAI601 편집 원칙의 기준 문서로 관리하고 새 지시는 여기에 반영한다.
